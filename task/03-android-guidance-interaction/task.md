# 大任务 3：Android 端引导交互能力

## 任务目标

实现用户可感知的引导交互层，包括权限引导、辅助面板、屏幕高亮、提示气泡、语音播报和会话基础状态。

这个任务负责把“模型或假数据返回的结果”真正变成用户能看见、能听见、能理解的指引。

## 建议负责人类型

- 主负责人：Android 工程师
- 协作角色：产品/设计

## 前置依赖

- 大任务 1 已完成工程骨架
- 大任务 2 已能拿到基本页面上下文
- 一版服务端响应 schema 已定义

## 范围

包含：

- 首页或会话入口页
- 权限引导页
- 无障碍开启引导流程
- 辅助面板或会话控制入口
- 覆盖层高亮框
- 半透明遮罩
- 文案气泡
- 基础箭头提示
- TTS 播报
- 当前会话状态管理

不包含：

- 复杂历史记录系统
- 高级动画和复杂视觉设计
- 自动代点

## 输入

- 服务端响应 schema
- mock 响应数据或真实服务端响应

## 输出

- 可操作的权限引导流程
- 可显示的 overlay 指引层
- 可播报的语音提示
- 一套最小会话状态流

## 子任务拆分

1. 设计并实现权限引导页。
2. 实现无障碍服务开启流程提示。
3. 实现辅助会话入口和会话控制 UI。
4. 实现 overlay 容器与渲染逻辑。
5. 根据 `target.bounds` 画高亮框。
6. 根据 `answer` 和 `caution` 显示提示气泡。
7. 根据 `action` 类型选择箭头或文案提示。
8. 接入 `TextToSpeech` 播报。
9. 建立当前轮请求、响应、状态的管理结构。

## 验收标准

- 用户能进入权限引导页面并完成基础授权流程。
- 给定一份 mock 响应，屏幕能正确画出高亮区域。
- 提示气泡位置和文案可理解。
- TTS 能正常播报返回文案。
- 高亮区域无明显偏移。

## 依赖和解耦建议

- 服务端未完成时，先使用固定 mock 响应开发 overlay。
- 先保证“有框、有文案、有播报”，再做视觉优化。

## 典型风险

- overlay 坐标和实际控件不对齐。
- 文案显示位置遮挡页面关键区域。
- TTS 播报时机与 UI 更新不同步。

## 管理检查点

- 验收时必须让开发用 mock 数据现场演示高亮和播报。
- 不要只听“UI 做好了”，要看是不是能吃下真实 schema。
- 重点关注提示是否真的容易理解，而不是只看样式。
