## 子任务 2.1：无障碍服务接入

### 目标

让 app 能注册并启用 AccessibilityService。

### 输出

- 无障碍服务可在系统设置中开启
- 服务启动后能收到窗口变化事件

### 验收

- 真机演示开启流程
- 能看到服务实际进入工作状态

———

## 子任务 2.2：节点树读取与标准化

### 目标

读取当前活动窗口根节点，并输出标准化节点数组。

### 输出

- 原始节点树读取逻辑
- 标准化节点对象结构
- 关键节点筛选逻辑

### 验收

- 至少 2 到 3 个页面能导出节点结构
- 节点结果包含：
    - text
    - contentDescription
    - className
    - clickable
    - enabled
    - bounds

———

## 子任务 2.3：截图能力接入

### 目标

获取当前页面截图，并形成可后续上传的图片结果。

### 输出

- takeScreenshot() 接入
- 图片压缩逻辑
- imageWidth / imageHeight 获取逻辑

### 验收

- 能在真机上拿到截图
- 截图可落盘或可用于后续上传
- 截图尺寸信息正确

———

## 子任务 2.4：坐标与尺寸统一

### 目标

统一：

- 屏幕尺寸
- 图像尺寸
- 节点坐标基准

### 输出

- screenWidth / screenHeight
- imageWidth / imageHeight
- 坐标规则说明
- 一份可复用的映射逻辑

### 验收

- 节点 bounds 与屏幕坐标语义一致
- 后续 overlay 能基于这套规则画框，不出现明显偏移

———

## 子任务 2.5：采集对象组装

### 目标

把节点树、截图、尺寸信息整理成后续网络层可直接消费的请求对象。

### 输出

- metadata 结构
- 截图文件对象
- 一份本地 mock 样本

### 验收

- 可以生成一份完整采集对象
- 后续 network 层不需要再二次猜字段

———

# 依赖关系

按真正执行顺序，我建议这样看：

1. 先做 无障碍服务接入
2. 再做 节点树读取与标准化
3. 并行推进 截图能力接入
4. 再做 坐标与尺寸统一
5. 最后做 采集对象组装

其中：

- 截图能力接入 和 节点树读取 可以部分并行
- 采集对象组装 不要太早做，因为前面字段还会变

———

# 风险点

你作为管理最该提前盯住的风险有 3 个：

1. 节点树质量不足

- 某些页面可能节点很弱
- 不要只测一个“好页面”

2. ROM / 真机差异

- 一个品牌能跑不代表别的品牌也稳
- 至少要有 2 台不同设备更理想

3. 坐标错位

- 这是最常见又最致命的问题之一
- 截图、节点、屏幕尺寸三者不统一，后面高亮一定偏

———

# 管理检查点

你验收这个任务时，不要只问“做完了吗”，要问：

1. 现在能不能现场开启无障碍服务？
2. 能不能现场抓一个真实页面的节点树？
3. 节点结果里有没有 clickable + bounds？
4. 能不能拿到截图？
5. 有没有导出一份本地样本？
6. 测了哪几个 App？哪几个页面失败了？
7. 坐标语义现在有没有明确文档？
