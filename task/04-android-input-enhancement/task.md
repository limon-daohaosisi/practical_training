# 大任务 4：Android 端输入增强能力

## 任务目标

补齐用户问题输入和页面文本补充能力，让客户端能获得“用户问了什么”和“页面上额外写了什么”，为服务端分析提供更完整上下文。

## 建议负责人类型

- 主负责人：Android 工程师

## 前置依赖

- 大任务 2 已具备基础采集能力
- 大任务 3 已具备基本会话入口
- 一版请求 schema 已确定

## 范围

包含：

- `SpeechRecognizer` 语音识别
- 本地 OCR `ML Kit`
- OCR 结果归一化
- 语音文本与页面上下文组合
- 请求发送前的输入组织
- 基础敏感字段脱敏

不包含：

- 连续语音对话
- Realtime 音频链路
- 复杂多语言识别

## 输入

- 当前页面截图
- 当前页面节点树
- 用户语音输入
- 请求 schema

## 输出

- 用户问题文本
- OCR 文本结构
- 一份可发送给服务端的完整请求对象

## 子任务拆分

1. 接入 `SpeechRecognizer`。
2. 设计语音提问触发方式和结束方式。
3. 处理语音识别成功、失败、超时状态。
4. 接入本地 OCR。
5. 对 OCR 结果做结构化整理。
6. 合并节点树文本和 OCR 文本摘要。
7. 对密码框、验证码等敏感内容做基础脱敏。
8. 将语音文本、截图、节点树、OCR 组合成统一请求体。

## 验收标准

- 用户能通过语音提出问题并得到文本结果。
- OCR 能在典型页面补出部分节点树缺失文本。
- 服务端请求体包含问题、截图、节点树、OCR、设备信息。
- 敏感字段不会原样裸传。

## 依赖和解耦建议

- 服务端未完成时，可先将请求体输出到本地日志或文件，确认结构正确。
- OCR 效果不稳定时，先验证格式通路，后优化识别策略。

## 典型风险

- 语音识别成功率受环境噪音影响。
- OCR 结果噪声较大。
- 节点树和 OCR 之间信息重复，导致请求冗余。

## 管理检查点

- 不只看“识别出了文字”，还要看最终请求体是否完整。
- 让开发演示几个实际页面，确认 OCR 的补充价值。
- 验证敏感字段处理，不要等到上线前再想。
