# 大任务 1：项目基础与技术验证

## 任务目标

建立 Android 端和服务端的最小可开发骨架，明确 MVP 边界、统一数据结构，并完成第一阶段技术验证的准备工作。

这不是为了做完整功能，而是为了让后续任务可以并行推进，并且避免 Android 和服务端在接口定义上互相等待。

## 建议负责人类型

- 主负责人：技术负责人或项目 owner
- 协作角色：Android 工程师、后端工程师、产品/测试

## 前置依赖

- 无

## 范围

包含：

- 仓库目录结构确定
- Android 项目基础骨架确认
- 服务端项目基础骨架确认
- MVP 范围确认
- 统一请求/响应 schema 初稿
- POC 验收方式定义

不包含：

- 真正的无障碍采集逻辑
- 真正的模型分析逻辑
- 完整 UI 和业务流程

## 输入

- `PROJECT_PLAN.md`
- 当前仓库目录
- 你已经确认的 MVP 范围

## 输出

- 可用的仓库结构
- Android 项目骨架
- server 项目骨架定义
- 一版统一数据结构文档
- 一版 POC 验收标准

## 子任务拆分

1. 确认仓库目录结构。
2. 确认 Android 端工程位置和模块边界。
3. 确认 server 端目录结构和技术栈。
4. 定义客户端到服务端的请求字段。
5. 定义服务端到客户端的响应字段。
6. 明确 MVP 做什么、不做什么。
7. 写出 Phase 0 的验收标准。
8. 准备一份 mock 数据示例，供 Android 和服务端并行开发。

## 关键接口边界

至少要先定清楚以下内容：

- 截图上传格式
- 节点树 JSON 结构
- OCR 文本结构
- 用户问题字段
- 服务端返回的 `target.bounds`
- 服务端返回的 `answer`、`action`、`confidence`、`caution`

## 验收标准

- 团队对 MVP 范围没有分歧。
- Android 和服务端都知道自己要对接的字段结构。
- 至少存在一份可以用于联调的 mock 请求和 mock 响应。
- 已定义 POC 成功标准：
  - 能跨 2 到 3 个常见 App 进行验证
  - 能完成“高亮无明显偏移”的基础验收

## 典型风险

- 任务边界不清，导致后面返工。
- 接口字段定义过晚，导致 Android 和服务端互相等待。
- 一开始把第二阶段内容混进 MVP。

## 管理检查点

- 这个任务有没有产出真实 schema，而不只是口头约定。
- 是否明确列出 MVP 不做项。
- 是否给后续任务准备好了 mock 数据和联调标准。
